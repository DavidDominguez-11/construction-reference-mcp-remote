
# Agent Brief — Construction Reference Remote MCP Server

## 1. Repository purpose

This repository contains the remote MCP server for the CC3067 MCP project.

The server provides simple material-reference information for small construction projects:

- Houses.
- Small buildings.
- Offices.
- Commercial spaces.

It runs remotely through HTTP/HTTPS and is deployed as a Docker container to Google Cloud Run.

It will be used by the `mcp-construction-host` application.

## 2. Repository responsibility

This repository must implement:

1. A remote MCP server using direct JSON-RPC 2.0.
2. HTTP/HTTPS communication compatible with MCP.
3. Tool discovery through `tools/list`.
4. Tool execution through `tools/call`.
5. Material-reference data stored locally in the repository.
6. Docker configuration.
7. Google Cloud Run deployment configuration and documentation.
8. Local testing instructions.
9. Documentation that supports the Wireshark analysis required by the course.

The remote server functionality may be simple. Its purpose is to demonstrate a real remote MCP connection, deployment, and network analysis.

## 3. Domain context

The server provides reference information about construction materials.

It does not provide live market prices, professional estimates, legal approval, or financial advice.

All material references are illustrative and must include a disclaimer that prices can vary because of:

- Location.
- Supplier.
- Quality.
- Date.
- Quantity.
- Delivery conditions.
- Labor conditions.

The initial location context is Guatemala and the reference currency is Guatemalan quetzal (`GTQ`).

## 4. Manual MCP requirement

Do not use an MCP SDK, MCP server library, MCP transport library, or MCP helper package.

The server must manually implement:

- JSON-RPC 2.0 parsing and serialization.
- JSON-RPC request validation.
- JSON-RPC responses.
- JSON-RPC error responses.
- `initialize` request handling.
- `notifications/initialized` notification handling.
- `tools/list` request handling.
- `tools/call` request handling.
- Unknown method errors.
- Invalid parameter errors.
- Internal error handling without exposing stack traces.
- HTTP request and response handling for JSON-RPC messages.

A standard Python HTTP framework such as FastAPI may be used only for HTTP routing and server execution. It must not replace MCP or JSON-RPC logic.

## 5. HTTP transport requirements

The MCP endpoint must be exposed at:

```text
/mcp
````

The server must:

* Accept JSON-RPC requests through HTTP `POST`.
* Return `application/json` responses for normal request/response interactions.
* Validate request content type.
* Return meaningful HTTP errors for invalid HTTP requests.
* Return JSON-RPC errors for valid HTTP requests containing invalid JSON-RPC messages.
* Support configurable request timeouts.
* Never log secrets.
* Provide a `GET /health` endpoint for Cloud Run health verification.

The MCP host will use the public HTTPS URL generated by Cloud Run.

## 6. Required MCP tools

### 6.1 `get_material_reference`

Returns general reference information for a material.

Parameters:

```json
{
  "material_name": "concrete block 15 cm",
  "location": "Guatemala"
}
```

`location` is optional and defaults to `Guatemala`.

The result must include:

* Canonical material name.
* Category.
* Unit of purchase.
* Reference price range.
* Currency.
* Reference update date.
* Location.
* General observations.
* Disclaimer.

Example result:

```json
{
  "material_name": "concrete block 15 cm",
  "category": "masonry",
  "unit": "unit",
  "reference_price_range": {
    "minimum": 8.0,
    "maximum": 11.0,
    "currency": "GTQ"
  },
  "reference_updated_at": "2026-09-05",
  "location": "Guatemala",
  "observations": [
    "Verify strength, dimensions, and supplier delivery conditions."
  ],
  "disclaimer": "Reference values only. Actual prices may vary by supplier, quality, location, date, quantity, and delivery conditions."
}
```

The tool must return a clear tool-level error when the material is not found.

## 7. Data requirements

Material reference information must come from a structured local JSON data file.

Recommended location:

```text
src/construction_reference_mcp_remote/data/material_references.json
```

The initial data set must include at least:

* Concrete block 10 cm.
* Concrete block 15 cm.
* Cement.
* Sand.
* Gravel.
* Reinforcing steel bar.
* Electrical conduit.
* Electrical cable.
* PVC pipe.
* Ceramic floor tile.
* Interior paint.

Each material record must include:

* Identifier.
* Canonical name.
* Supported aliases.
* Category.
* Unit.
* Minimum reference price.
* Maximum reference price.
* Currency.
* Update date.
* Observations.

The data set is illustrative. It must not claim to be live market data.

## 9. Docker requirements

The repository must contain:

* A `Dockerfile`.
* A `.dockerignore`.
* Clear local container build instructions.
* Clear local container run instructions.

The container must:

* Use Python 3.12.
* Install only required dependencies.
* Expose the application port.
* Read the HTTP port from the `PORT` environment variable, with a safe local default.
* Listen on `0.0.0.0`.
* Start the HTTP server automatically.
* Not contain credentials or API keys.

The server must be testable locally through Docker before deployment.

## 11. Wireshark analysis support

The project report requires a Wireshark capture between the MCP host and this remote server.

The README or `docs/deployment.md` must include:

* The expected request sequence:

  1. TCP connection.
  2. TLS handshake.
  3. HTTP/HTTPS request.
  4. JSON-RPC `initialize`.
  5. `notifications/initialized`.
  6. `tools/list`.
  7. `tools/call`.
  8. JSON-RPC responses.
* A reminder that public Cloud Run traffic uses HTTPS, so JSON-RPC content is normally encrypted inside TLS.
* Instructions to correlate Wireshark packets with the host JSON-RPC interaction log.
* A note that TLS decryption may be configured only in a controlled local development environment if raw JSON-RPC inspection in Wireshark is required.
